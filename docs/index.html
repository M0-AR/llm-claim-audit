What this is, in plain language

A popular talk about AI tools is a snapshot of a moving target. This repository asks a simple, measurable question: if you re-checked every checkable statement today, which ones would still be true?

The one-sentence version

Some facts age in years — tokenizer sizes, caffeine content, historical dates. Others age in months — pricing tiers, model names, default settings. This audit measures both, and the gap between them is the story.

  • 17 claims extracted with quotes, dates, methods and sources
  • 4 experiments over committed data — no live internet needed
  • 1 preregistered experiment committed but deliberately not executed
  • 0 API keys used anywhere

Why “two-speed”?

Classify every claim into one of two kinds:

  • Artifact facts — describe objects: a tokenizer's vocabulary, a paper's result, a milligram count. They decay in years.
  • Product surfaces — describe what a product looks like today: tiers, model line-ups, interface defaults. They decay in months.

In this ledger: artifact facts held 4 out of 4 times; era-dependent claims drifted 6 out of 10 times.

E5

Registered, not executed

discipline

A strict arithmetic test — 40 tasks of 12-digit × 8-digit multiplication, seed 20261017 — with a runner for any OpenAI-compatible endpoint and an exact-McNemar scorer was frozen before model contact. It is not executed here because this project used no API keys; the runner exits with code 2 without one, and the README claims nothing from it. The registration is committed so anyone can run it unmodified.

This is the honest alternative to fabricating results: a promise you can execute, not a number you can't check.

Questions

FAQ

Is this financial advice?
No. Market data appears only as a test rig: three independent free sources should agree, and the way they disagree should be structured (calendars, timestamps), not random. The experiment measures data quality, not prices.
Does the repository need API keys or internet access?
No. Snapshot mode runs offline from committed data — the Docker service proves it with networking disabled. One preregistered experiment (E5) could use an API key, and that is exactly why it is disclosed as registered, not executed.
Doesn't a 60% drift rate mean the talk was wrong?
No — it means the talk was precise about a moving product. Claims were accurate when made; the audit measures decay, and the two-speed split shows the decay is categorical (product surfaces) not random. That is the useful signal.
What is a Wilson interval and why 31–83%?
It is a confidence interval for a proportion that behaves correctly with small samples. With 6 of 10 claims drifted, the point estimate is 60%, but honest uncertainty spans 31–83% — tiny samples cannot pin a rate down harder than that.
What is a bootstrap and why does it demote the leaderboard?
Resampling the benchmark items with replacement (10,000 times) simulates “what if the benchmark had drawn different questions from the same distribution.” The top model keeps rank 1 in only 44.9% of those worlds — so “#1” is a coin flip, not a verdict.
How do I know the numbers were not hand-edited?
Three ways: the pipeline rewrites every result file from committed inputs in about a second; the manifest SHA-256-hashes each artifact; and the test suite checks tolerances, identities and structures (weekend days, Wilson bounds, McNemar value) so tampering breaks the build.
How do I put this page online for free?
GitHub Pages, branch deployment: repository Settings → Pages → Build and deployment → Source: “Deploy from a branch” → branch main, folder /docs → Save. Your site appears at the address GitHub shows, typically https://<username>.github.io/<repository>/ within a minute.
Can I reuse this method on another talk or document?
Yes — that is the point. Copy the ledger schema (quote, date, method, source, status), classify claims as artifact facts vs product surfaces, verify against primary sources, and compute the drift statistic. The 5-step method section of the README is written to be reusable.
Plain-language dictionary

Glossary

LLMA large language model — software that predicts text; the “chatbots” this audit is about.
TokenThe unit models read and write. “Hello world” is a handful of tokens, not letters or words.
Vocabulary / encodingThe fixed dictionary a tokenizer can emit. GPT-4o's o200k_base has 200,019 entries.
Knowledge cutoffThe date a model's training data ends — after which it knows nothing new unless given tools.
BenchmarkA fixed test set used to score models. Resampling its questions is how E3 tests stability.
LeaderboardA ranking of models by benchmark scores. E3 shows the top ranks are statistical ties.
EloA chess-style rating system used by model arenas; near-equal ratings mean near-equal strength.
Basis point (bps)One hundredth of a percentage point (0.01%). 12.57 bps ≈ 0.13% — the median vendor disagreement in E2.
Reference / fixing rateAn official daily exchange rate (here: the ECB's ~16:00 CET snapshot), used as the benchmark in E2.
BootstrapResampling data with replacement thousands of times to measure how stable a result is.
PreregistrationFreezing a test's method and hypotheses before seeing results — the discipline behind E5's “registered, not executed” status.
SHA-256 manifestA fingerprint list of every file produced. Matching hashes prove two runs (e.g. host and offline container) agree.
